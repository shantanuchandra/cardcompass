## System-level findings

| Priority | Mishap | Evidence | Required change |
|---|---|---|---|
| **P0** | Accessibility text zoom is blocked | `MaterialApp` forces `TextScaler.linear(1.0)` | Respect OS/browser scaling; test at 100%, 150%, and 200%. |
| **P0** | Core fonts are not bundled | Theme references Manrope, Fraunces, and IBM Plex Mono; `pubspec.yaml` has no font assets | Bundle font files or use one reliable packaged family; remove silent fallback. |
| **P0** | Visible controls do nothing | Four Settings rows and Dashboard “View All” actions use empty callbacks | Implement destinations or render them as non-interactive/“Coming soon.” |
| **P1** | Type is too small for financial evidence | Repeated 8–11 px labels on login, movie, cards, ledger; landing reaches 8 px | Use 12 px minimum and increase line height/contrast for trust-critical copy. |
| **P1** | Theme semantics conflict | Global `Brightness.dark` with Paper surfaces and Ink text | Create semantic light/dark schemes; avoid control defaults inheriting the wrong brightness. |
| **P1** | Authenticated screens lack a shared page grammar | Many one-off `TextStyle`, border, header, KPI, and card definitions | Standardize `PageHeader`, `EvidenceLabel`, `MetricCard`, `EmptyState`, `ErrorState`, and `ActionRow`. |
| **P1** | Mobile density is layout-led, not task-led | Three KPI cards remain in one row; five-item bottom nav uses 10 px labels | Stack/scroll secondary KPIs; shorten labels and preserve 44 px targets. |

## Page-by-page QA

| Page | Status | Main mishap | Change to make |
|---|---|---|---|
| Landing | 🟡 | Strong hero, but mobile page is ~7,500 px tall and has 11 section headings; application form competes with product proof | Keep hero + recommendation demo + trust + waitlist; collapse secondary proof and move “how it works” below conversion. |
| Best-card calculator | 🟡 | Large editorial hero pushes the utility below the fold | Put the first inputs/result preview beside the headline on desktop and directly after one short intro on mobile. |
| Milestone tracker | 🟡 | Same long editorial preamble pattern delays task completion | Lead with “current spend / target / deadline,” then explain methodology after the result. |
| Movie-offer calculator | 🟡 | Inputs are useful, but explanatory density exceeds the decision | Show “best effective ticket price” first; put assumptions/caps in expandable evidence. |
| Privacy / Data & Security / Terms / Disclaimer | 🟡 | Complete and trustworthy, but 11 px legal copy and repeated navigation reduce readability | 15–16 px body, 65–75 character measure, sticky local contents, clearer last-updated block. |
| Login | 🟡 | Excellent split-screen composition; receipt evidence and legal copy drop to 8–9 px, while the secondary preview can compete with the sign-in job | Raise small copy, simplify receipt rows, keep Google CTA visually dominant, and use a clear loading/error state in-place. |
| Splash / auth callback | 🟡 | Brand-aligned but offers little explanation during a potentially slow OAuth exchange | Add explicit stages: “Securing session” → “Loading wallet”; provide recovery after a timeout. |
| App shell / navigation | 🟡 | Strong Ink/Paper framing; five mobile labels are cramped and “Ledger” differs from the public “Transactions” language | Use one vocabulary; consider 4 primary tabs + More, or shorten Movie Deals to Movies. |
| Dashboard | 🔴 | Fixed three-up KPIs make every metric equal; two “View All” actions are dead | Feature one “best next action,” stack supporting KPIs responsively, and wire every CTA. |
| Cards | 🟡 | Clear list, but generic card icon/issuer stripe undersells recognition; credit limit can dominate card identity | Use issuer/card art or monogram, surface last sync/status, and demote limit to secondary metadata. |
| Add card | 🟡 | Two-step interaction has no visible progress, and optional sensitive-looking fields lack rationale | Add “1 Search / 2 Confirm,” explain why last four/name are optional, validate inline, preserve search state. |
| Card detail | 🔴 | Very long, dense screen with many 9–11 px labels and multiple equal-weight sections | Create a summary header, “use this card for” block, milestone progress, then tabs/accordions for details and history. |
| Ledger / transactions | 🔴 | Three-up KPI row, filters, grouping, chart, and rows compete; error state exposes raw exception text | Make spend the primary metric, collapse filters into a sheet, simplify rows, and translate errors into user actions. |
| Movie optimizer | 🔴 | Technical copy (“query combinations,” “specifications”) and paired fixed rows feel like an internal tool | Use plain-language questions, stack fields on narrow widths, and return one recommendation with savings/cap explanation. |
| Movie results | 🟡 | Dense evidence labels make comparison hard | Rank the winner first; compare alternatives in a compact table; hide calculation detail behind “Why?”. |
| Settings | 🔴 | Four rows look actionable but have empty callbacks | Implement them before release or visibly disable/remove them; add data deletion/export and notification state. |
| Empty / loading / error states | 🟡 | Present, but visual/copy behavior varies and some errors expose implementation details | Standardize state components with one primary recovery action and human-readable messages. |
| 404 | 🟢 | On-brand fallback exists | Add two obvious exits: Home and Sign in. |

## Recommended execution order

| Phase | Scope | Exit criterion |
|---|---|---|
| **1 — Trust blockers** | Restore text scaling, bundle fonts, remove dead interactions, normalize error copy | Keyboard + 200% text scale pass; no inert affordances |
| **2 — Core journeys** | Dashboard hierarchy, add-card flow, ledger density, movie input/result | Each page has one unmistakable primary task and responsive mobile state |
| **3 — Systemize** | Shared components, semantic light/dark themes, state patterns | New pages can be composed without one-off text/border styles |
| **4 — Conversion polish** | Shorten landing, lift utility actions, improve legal readability | Product action appears within first viewport; mobile funnel is materially shorter |
