# CardCompass

> Machine-readable product and source guide. Public claims here are limited to behavior visible in the current product and landing implementation.

## Product

- Name: CardCompass
- Website: https://cardcompass.in/
- Market: India
- Category: credit-card reward decision support
- Status: early access / waitlist
- Support and data requests: support@cardcompass.in

CardCompass is being built for people managing several Indian credit cards. It aims to present a card choice with estimated value, caps, milestone context, caveats, source and verification date. Recommendations are informational estimates, not financial advice or issuer guarantees.

## Current product flows

### Card and statement organisation

Signed-in users can associate cards from the CardCompass catalog with their account. Current application flows use catalog identity, last four digits, optional holder/limit fields, and statement/due dates; they do not ask users to enter a full card number, CVV, PIN, OTP or banking password.

### Gmail read-only statement import

Google OAuth requests Gmail read-only access (`gmail.readonly`) and birthday read access (`user.birthday.read`) in addition to profile scopes. The app searches for statement-like emails with PDF attachments, reads matching email/attachment metadata and downloads a selected statement PDF for processing. Read-only access does not authorise sending, editing or deleting Gmail messages.

### PDF extraction and password handling

PDF text is extracted in the running app. A password-protected statement can use date-of-birth/card-pattern candidates or a statement PDF password entered by the user. Successful statement PDF passwords and learned patterns are cached locally in app/browser preferences by the current code. The original PDF is not uploaded through the current statement repository path.

### Gemini processing

Extracted and pruned statement text is sent through an authenticated Supabase edge-function proxy to the Google Gemini Generative Language API. Gemini returns structured statement and transaction data. This AI processing is not solely local or on-device.

### Supabase persistence

Supabase provides authentication, database storage, waitlist RPCs and the Gemini proxy. It stores account/profile, Gmail processing metadata, card, transaction and statement records for product users. It separately stores waitlist email, application answers, consent timestamps and attribution fields for early-access operations.

### Analytics

The public landing page uses Plausible. CardCompass strips query parameters and URL fragments before analytics transport, blanks referrer data and allow-lists non-sensitive event context. Waitlist attribution is handled separately and submitted to Supabase when the visitor joins.

## Calculator limits

The public calculators use arithmetic based on visitor inputs. They do not query issuers or confirm merchant category, eligibility, benefit inventory, posting, cap state or reward fulfilment. Official issuer and merchant terms remain authoritative.

## API

CardCompass does not currently offer a public developer API.
